# DLS NLP Final: агент релевантности организаций

**Выбранная тема DLS: «LLM-агенты: оценка релевантности организаций запросам на Яндекс.Картах».**

Проект решает официальную задачу DLS: по широкому запросу и карточке организации предсказывает один из трёх классов релевантности:

- `1.0` — `RELEVANT_PLUS`, организация полностью соответствует запросу;
- `0.1` — `RELEVANT_MINUS`, соответствие частичное;
- `0.0` — `IRRELEVANT`.

## Что реализовано

- сильный baseline: word/char TF-IDF + трёхклассовая Logistic Regression;
- агент с поиском подтверждающих фрагментов в карточке и настоящим внешним web-search tool;
- retrieval похожих размеченных примеров только из train;
- структурированные план поиска и решение через Instructor/OpenRouter (`tencent/hy3`);
- честная абляция baseline → retrieval-agent;
- accuracy, macro/weighted F1, per-class metrics, confusion matrix и анализ ошибок;
- русскоязычный FastAPI-интерфейс и пакетный API.

## Защита от утечки

Все параметры выбираются на фиксированном holdout из `data_for_train.jsonl`. После выбора модель переобучается на полном train, а `data_for_eval.jsonl` используется один раз для итогового отчёта. Eval не используется для настройки промпта, весов или порогов.

## Воспроизведение

Скачайте официальный архив: <https://disk.yandex.ru/d/FK8B0ONM67VHCA>.

```bash
pip install -r requirements.txt
python scripts/run_experiment.py \
  --train /path/to/data_for_train.jsonl \
  --eval /path/to/data_for_eval.jsonl
pytest -q
uvicorn app:app --host 0.0.0.0 --port 8000
```

Для реальных запросов задайте `OPENROUTER_API_KEY`, `USE_INSTRUCTOR=1` и
`OPENROUTER_MODEL=tencent/hy3` в переменных Railway или локальном `.env`.
Образец находится в `.env.example`; секреты не входят в Git. Обращения к LLM
и веб-поиску платные. Сервис рассчитан на небольшую демонстрацию, а не на
неограниченную публичную нагрузку; задайте лимит расходов ключа у провайдера.
В одном процессе одновременно допускаются два LLM-запроса и по умолчанию
60 карточек за час (`LLM_REQUESTS_PER_HOUR`); при превышении возвращается 429.
Это ограничение сбрасывается при рестарте и не заменяет общий бюджет API-ключа.

```bash
python scripts/audit_live_agent.py
```

Команда проверяет шесть сценариев с реальными API-вызовами. Это регрессионная
проверка, не оценка качества на датасете. Результат с фактическим временем
запуска сохраняется в `reports/live_agent_audit.json`.

Для браузерной проверки: `pip install playwright`, `playwright install chromium`,
затем `python scripts/audit_ui.py --url http://127.0.0.1:8000` при запущенном
сервере. Она проверяет реальный baseline и скачанный JSON, а ошибку LLM
моделирует отдельно, без платных запросов. Скриншоты сохраняются в `reports/ui_audit`.

Архивный эксперимент воспроизводится из Git-коммита `86816e6` с его исходным
промптом и моделью; ответы внешнего LLM API не гарантируют побитовую повторяемость.
Текущий `run_official_llm_agent.py` использует обновлённый промпт и сохраняет
результаты отдельно в `artifacts/current_llm`, не затирая архив.

## API

- `GET /` — интерактивная демонстрация;
- `GET /metrics` — сохранённые метрики;
- `POST /score` — один запрос и одна организация;
- `POST /batch_score` — пакетная оценка;
- `GET /health` — проверка сервиса.
- `GET /capabilities` — доступность конфигурации LLM (без раскрытия ключа).

В форме по умолчанию выбрана LLM. В режиме «Решает агент» модель сначала
возвращает проверенный план: нужен ли поиск и какой запрос отправить.
Внешний поиск выполняется через OpenRouter Web / Exa; найденные источники
передаются финальному решению. Есть также режимы «Всегда» и «Выключен».
Отсутствие ссылок или ошибка поиска отмечаются отдельно и не считаются
доказательством отсутствия услуги. Источники могут ошибаться: проверьте
совпадение организации и адреса в трассе.

Режим Baseline не вызывает LLM или интернет. Для API используйте
`use_llm: false`, чтобы выбрать его явно. `POST /score` по умолчанию
использует `use_llm: true, search_mode: "auto"`. Пакет ограничен 10 карточками;
параметры каждой учитываются отдельно. Пустые обязательные поля дают HTTP 422,
отсутствие конфигурации LLM — 503, сбой провайдера — 502, без скрытого fallback.
Самооценка LLM не выдаётся за калиброванную вероятность; три вероятности
классов возвращаются только для baseline. Решение и трассу можно скачать в JSON.
