# Краткий сценарий защиты NLP-проекта

1. Открыть Railway-интерфейс и показать итоговый класс, объяснение и трассу. Самооценка LLM не равна калиброванной вероятности; вероятности классов доступны в режиме Baseline.
2. Выбрать LLM и поиск «Решает агент», показать `plan_search`, затем при нехватке данных — `public_web_search` и `llm_decision`. При сбое API показывается ошибка, не результат другой модели.
3. Открыть `reports/final_report.md` и объяснить протокол без утечки: настройка только на train-holdout, eval один раз.
4. Сравнить baseline, retrieval-agent и structured LLM-agent на одном official eval из 570 строк.
5. Подчеркнуть честный результат: LLM-agent повышает macro F1 и recall пограничного класса, но не accuracy; retrieval не переносит holdout-прирост на очищенный eval.
6. Показать `official_llm_predictions.jsonl`: для каждой строки сохранены confidence, rationale, evidence и похожие размеченные train-примеры.

Главный вывод: архивный эксперимент показывает ограничения шумной train-разметки.
Новая демонстрация использует другой backend и автоматический поиск; её небольшая
регрессионная проверка не заменяет оценку на всех 570 примерах. Не смешивайте эти результаты.
