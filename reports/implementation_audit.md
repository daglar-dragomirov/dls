# Проверка обновлённой демонстрации

## Что исправлено

- Форма раньше вызывала baseline независимо от наличия LLM. Теперь режимы
  разделены; по умолчанию используется Tencent Hy3 через OpenRouter.
- Интернет-выдача раньше не влияла на baseline. Новый путь: план LLM,
  поиск OpenRouter Web / Exa при необходимости, решение по карточке и источникам.
- При недоступной LLM больше нет скрытого fallback. Ошибки конфигурации,
  провайдера, пустых полей и лимитов возвращаются явно.
- Пакетный API учитывает параметры каждой карточки. Есть ограничения длины,
  размера пакета, количества одновременных и часовых LLM-запросов.
- Форма сбрасывает устаревший результат и блокирует изменения во время запроса.
  JSON скачивается вместе с источниками и трассой. Ответ вставляется в DOM
  как текст, а не как исполняемый HTML.
- Классы модели заданы смысловыми именами, которые код переводит в официальные
  `0.0 / 0.1 / 1.0`. Это устранило наблюдавшуюся путаницу между числовой меткой
  и правильно сформулированным объяснением Tencent.

## Проверки

`pytest -q`: 24 теста. Они проверяют данные, метрики, API, выбор инструментов,
передачу веб-доказательств, ошибки, лимиты и соответствие смысловых классов меткам.
Внешние LLM-вызовы здесь заменены контролируемыми ответами.
Отдельно проверяется безопасная диагностика HTTP-ошибок провайдера: наружу
не передаются сырые ошибки с содержимым запросов.

`scripts/audit_live_agent.py` отдельно выполняет шесть платных запросных сценариев:
полное соответствие, явное несоответствие, неподтверждённое условие, инструкция
внутри отзыва, принудительный поиск и поиск по решению самого агента.
Полные ответы, реальные длительности и статус каждого сценария находятся
в `live_agent_audit.json`. Это ручной регрессионный набор, не independent benchmark.

`scripts/audit_ui.py` проверяет реальный baseline через браузер, содержимое
скачанного файла, устаревшее состояние, пробелы вместо запроса, переключение
режимов и контролируемую ошибку API. Проверены ширины 1440, 390, 320 px,
горизонтальное переполнение и ошибки JavaScript. Скриншоты в `ui_audit/`.
Дополнительно во встроенном браузере вручную выполнен реальный LLM-запрос:
`structured_llm_agent`, модель `tencent/hy3`, успешное скачивание JSON.

## Что эта проверка не доказывает

Новая версия не проходила заново весь official eval. Июльские метрики на 570
примерах сохранены отдельно и подписаны как архивные. Максимальный балл или
отсутствие ошибок на любых запросах не гарантируются. Интернет-источники и
сама модель могут ошибаться, а доступность OpenRouter зависит от провайдера.
Во время работы прежняя модель OpenAI возвращала 403; у Tencent понадобился
переход с tool-call extraction на JSON Schema. Эти проблемы не скрыты baseline-ответом.

Для публичного сервиса отдельно требуются корректные переменные Railway:
`OPENROUTER_API_KEY`, `USE_INSTRUCTOR=1`, `OPENROUTER_MODEL=tencent/hy3`.
Наличие переменной с ключом ещё не доказывает работоспособность платёжного
аккаунта или модели; нужен успешный реальный запрос.
